# Subagent 与主 Agent 分工文档

## 目标

本轮改动聚焦三个数据链路问题：

- 评论区真实消息被过重去重误删。
- 礼物区特别关注用户因为缺少稳定 `userId/userLink` 导致标签丢失。
- 礼物区点击用户主页慢，因为事件首次渲染时没有可直达主页的身份字段。

核心原则：

- Subagent 负责查清问题、给出证据和风险。
- 主 Agent 负责控进度、统一改代码、统一验证。
- 不用昵称直接命中特别关注。
- 神秘人、匿名用户、贡献榜、在线观众 Top 等噪音身份不进入普通用户身份缓存。
- 先保证真实数据不丢，再处理重复数据。

## 主 Agent 职责

主 Agent 负责最终闭环：

- 拆分任务。
- 分派 subagent。
- 汇总 subagent 结论。
- 更新进度文档。
- 决定最终方案。
- 修改核心代码。
- 运行构建和回归验证。
- 输出最终影响范围和剩余风险。

主 Agent 直接负责的高风险文件：

- `apps/server/src/capture-service.ts`
- `apps/server/src/db.ts`
- `apps/server/src/types.ts`
- `apps/web/src/App.tsx`
- `apps/web/src/types.ts`
- `apps/server/src/collector.ts`

## Subagent A：评论去重专项

职责范围：

- 检查评论从采集到前端展示的完整链路。
- 找出评论真实丢失的位置。
- 判断后端去重、前端展示去重是否过重。
- 区分“真实重复发言”和“采集源重复推送”。

输出要求：

- 指出涉及文件和关键逻辑。
- 给出应保留的去重规则。
- 给出应缩短或移除的去重规则。
- 给出评论不丢、不重复的验收用例。

禁止事项：

- 不修改礼物区身份逻辑。
- 不修改 SQLite 表结构。
- 不修改特别关注规则。
- 不修改神秘人规则。

## Subagent B：SQLite 身份缓存专项

职责范围：

- 设计本地 SQLite 身份缓存表。
- 设计用户身份写入规则。
- 设计昵称变更处理方式。
- 设计同名冲突处理方式。
- 设计不能进入普通身份缓存的数据类型。

输出要求：

- 推荐表结构。
- 推荐索引。
- 推荐 upsert 规则。
- 明确 `userId/userLink/userName` 优先级。
- 明确神秘人、匿名用户、贡献榜等隔离规则。

禁止事项：

- 不启用礼物区身份补齐。
- 不修改前端展示。
- 不修改评论去重。

## Subagent C：礼物区身份与特别关注专项

职责范围：

- 分析礼物事件为什么经常缺少 `userId/userLink`。
- 分析礼物区特别关注标签漏命中的原因。
- 分析礼物区用户主页打开慢的原因。
- 设计礼物区身份补齐时机。

输出要求：

- 明确礼物区身份补齐必须发生在入库和 SSE 推送前。
- 明确补齐后要写入顶层 `LiveEvent.userId/userLink`。
- 明确什么时候允许补齐身份。
- 明确什么时候禁止补齐身份。
- 明确特别关注仍然只按 ID/link 命中。

禁止事项：

- 不用昵称直接命中特别关注。
- 不让神秘人、匿名用户、贡献榜昵称污染普通身份缓存。
- 不修改评论区去重。

## Subagent D：前端展示与交互回归专项

职责范围：

- 检查前端评论区、礼物区列表展示。
- 检查特别关注标签展示。
- 检查用户主页点击逻辑。
- 检查过滤功能、神秘人列表、自动跟随是否受影响。

输出要求：

- 前端影响面清单。
- 必须修改的位置。
- 不应该修改的位置。
- 回归风险点。
- 验收用例。

禁止事项：

- 不修改后端采集。
- 不修改 SQLite。
- 不改变业务规则。

## Subagent E：测试与验收专项

职责范围：

- 汇总 A/B/C/D 的结论。
- 输出最终回归测试清单。
- 输出打包前检查项。
- 输出回退开关建议。

输出要求：

- 评论不丢测试。
- 评论不重复测试。
- 礼物区特别关注测试。
- 礼物区主页打开速度测试。
- 神秘人隔离测试。
- SQLite migration 幂等测试。
- Excel 导出兼容测试。

禁止事项：

- 不直接打包。
- 不直接修改业务代码。

## 执行顺序

1. 第一轮并行：Subagent A、B、D 只读诊断。
2. 第二轮：Subagent C 基于 B 的身份缓存方案分析礼物区。
3. 第三轮：Subagent E 汇总验收清单。
4. 主 Agent 汇总结论并统一落地。
5. 主 Agent 构建验证并更新进度文档。
6. 需要发布时，主 Agent 按版本规则更新日志并打安装包。
