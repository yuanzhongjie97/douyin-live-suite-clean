## 1. 产品定位

糖三角是一款面向抖音直播间运营/场控/数据复盘人员的 Windows 桌面工具。它在用户完成抖音登录后，通过内嵌浏览器采集直播间公开可见互动数据，实时展示评论、进场、互动、礼物、神秘人和特别关注用户命中情况，并支持采集结束后的本地保存和 Excel 导出。

## 2. 目标用户

| 用户 | 诉求 |
| --- | --- |
| 直播运营人员 | 实时观察直播间互动质量、礼物和重点用户表现 |
| 场控人员 | 快速查看评论、进场、互动和送礼，及时响应 |
| 私域/客户运营 | 标记特别关注用户，命中时高亮并保留备注 |
| 数据复盘人员 | 采集结束后导出 Excel，留存评论、礼物和统计 |
| 技术/支持人员 | 通过诊断日志定位白屏、丢评论、资源缓存等问题 |

## 3. 产品目标

- 用户无需手动打开浏览器页面，直接使用 Windows 桌面客户端。
- 支持抖音登录态复用，尽量保证礼物、评论等数据完整采集。
- 高频直播数据下保持界面可用，不因大量消息明显卡顿。
- 停止采集后保留会话数据，支持导出和自动保存。
- 支持特别关注用户和神秘人识别，辅助运营判断。
- 出现白屏、评论丢失、浏览器异常时能提供可追踪诊断信息。

## 5. 核心用户流程

### 5.1 登录并开始采集

1. 用户启动桌面客户端。
2. Electron 启动本地服务并加载监控台。
3. 用户点击登录抖音，系统打开可见 Chromium 登录窗口。
4. 用户完成登录。
5. 用户输入直播间 URL。
6. 用户点击开始采集。
7. 系统复用登录态打开直播间，注入 DOM 观察器，开始接收事件。

验收标准：

- 未登录时开始采集应给出明确错误。
- 登录窗口可复用。
- 采集中不允许打开/关闭登录窗口。
- 直播间页面应尽量保持活跃，避免后台暂停。

### 5.2 实时查看数据

系统应实时展示：

- 评论
- 用户进场
- 用户互动
- 用户送礼
- 统计数据
- 神秘人列表
- 特别关注命中
- 当前会话/房间状态

验收标准：

- 新消息可自动跟随到底部。
- 用户手动滚动后不强制拉回底部。
- 高频事件以批量方式展示，避免逐条渲染造成卡顿。
- 评论/礼物长文本可换行，不遮挡。
- 无数据时展示清晰空状态。

### 5.3 神秘人识别

系统根据事件的昵称、用户 ID、主页链接、payload 等字段识别神秘人相关用户。

规则：

- 包含“神秘人”或“神秘王者”的身份字段可识别。
- 普通用户评论中仅 @ 神秘人，不应把普通用户误判为神秘人。
- 神秘人列表最多保留近期高活跃用户。
- 支持展开查看该用户最近活动。

验收标准：

- 神秘人列表不展示普通用户。
- 最新活动靠前。
- 点击用户名可尝试打开主页。
- 送礼、进场、评论均可作为活动来源。

### 5.4 特别关注用户

系统读取用户桌面或文档目录下的 `highlight_users.txt`。

支持格式：

```txt
用户ID 备注
1215343001 重要客户
*dou* 关注dou相关用户
```

规则：

- 每行一条配置。
- 支持用户 ID。
- 支持用户 ID + 备注。
- 支持通配符。
- 匹配应基于稳定身份字段，不应误命中 `douyin.com` 这类公共域名。
- 命中时标记区显示 `特别关注 备注`；消息正文用户名区恢复旧版口径，只显示原昵称，不把备注拼进正文用户名。

验收标准：

- 文件不存在时自动创建或给出明确状态。
- 中文备注不乱码。
- 评论和送礼均可高亮。
- 特别关注弹窗只展示命中消息。
- 打开主页仍基于原始身份，不基于备注文本。

### 5.5 停止、保存和导出

用户可以手动停止采集；当主播关播时系统可以自动停止。

要求：

- 停止采集后数据不清空。
- 停止后仍可查看和导出最近会话。
- 手动停止可保存到桌面目录。
- 关播自动停止可保存到文档目录下 `糖三角/自动导出`。
- 导出包含评论、进场、互动、礼物、日志和汇总统计。

验收标准：

- 无会话时导出应返回明确错误。
- 导出文件名应安全，不包含 Windows 非法字符。
- 导出应包含所有历史评论，不只包含当前前端展示数量。

## 7. 非功能需求

### 性能

- 高频消息下应使用批量推送和批量渲染。
- 大列表应虚拟滚动。
- 前端事件队列应设置上限，避免内存无限增长。
- 每会话数据库原始事件保留窗口仍用于控制本地存储和明细导出负载；2026-06-09 起统计口径改为尽量代表全量直播历史，通过会话级累计汇总保留新版本接收后的全量计数。
- 当前 UI 近期显示窗口沿用源码规则：评论 200、进场 120、互动 120、礼物 120、日志 220。
- Excel 导出必须明确区分“全量统计汇总”和“当前保留明细”。明细 sheet 只代表当前仍保留的原始事件；统计 sheet 尽量代表全量直播历史。

### 稳定性

- 采集页关闭或不可用时应记录错误并结束会话。
- 自动保存失败不应影响会话结束。
- 本地存储不可用时前端仍应能渲染。
- 静态资源缓存错误应有诊断日志。

### 安全

当前 P0 安全边界：

- 本地 API 只服务 Electron 桌面端。
- 服务启动生成运行期 token，并通过首屏 HttpOnly Cookie 授权桌面页面。
- 所有 `/api/*` 读写接口、SSE、导出接口都需要有效 Cookie；静态资源不鉴权。
- `Origin: null`、`file://`、`data:`、非 HTTP(S)、远程网页等非本机来源会被拒绝；带非法 Origin 的 `/api/*` 读取请求也直接返回 403。
- 开始采集只允许 `https://live.douyin.com/{roomId}`；登录/用户主页只允许必要抖音 HTTPS 页面。
- Electron 已升级到清除 high 审计项的版本；`exceljs -> uuid` moderate 风险继续保留风险接受记录。

### 可维护性

- 核心文件应逐步拆分，避免单文件承载过多职责。
- 核心采集器应恢复 TypeScript 检查。
- 建立统一测试入口和覆盖率。

## 11. V26.6.9.3 需求边界补充

## 12. 2026-06-10 P0 采集完整性边界补充

- 礼物名必须保留属于礼物自身的前缀字符；例如 `送你花花 x1` 的礼物名应为 `送你花花`，不能被清洗成 `你花花`。
- 独立送礼动作词仍应被识别并剥离；例如 `用户A 送 玫瑰 x1` 的礼物名应为 `玫瑰`。

- 本次修复不改变采集入口、入库结构、统计口径、Excel 导出结构、每会话原始明细 50000 条上限和特别关注展示口径。
- 真实直播间验收仍由用户最终拍板；若再次复现评论不完整，需要保留会话 ID、时间点、原始直播间可见文本和复制诊断信息继续定位。

## 15. 2026-06-11 P0 评论与礼物备注强闭环边界

- “不丢评论/消息/备注”的验收口径固定为数据库、统计、导出和诊断可追溯；UI 继续按近期窗口展示，评论 200、礼物 120，不新增全量历史 UI。
- 评论唯一键边界：有稳定 `sourceId` 的同一 DOM 重扫必须生成同一 `uniqueKey`，避免重复；无 `sourceId` 的连续相同评论必须可通过采集序号区分，避免误删真实重复发言。
- 后端新增采集完整性账本，记录评论和礼物的 raw received、filtered、deduped、db inserted、db ignored unique、bus published，以及礼物身份后到重新发布次数。
- 礼物备注边界：特别关注只按稳定身份匹配，候选包括顶层 `userId/userLink`、payload `userId/userLink`、从主页链接提取出的 sec_uid；仍不使用昵称兜底。
- 礼物身份后到时只补齐身份字段和 payload，不覆盖原始事件的 `id`、`createdAt`、`ingestSeq`；补齐后重新发布同一行给前端，触发备注重新计算。
- 复制诊断必须包含最近评论、最近礼物、持久化评论、持久化礼物、采集完整性账本、特别关注命中详情和命中字段 `matchedBy/matchedValue`。
- 本轮不改变直播 URL allowlist、采集启动/停止流程、SQLite 表结构、统计/导出口径、每会话原始明细 50000 条上限、特别关注展示口径和安装包版本。
