# 糖三角直播采集工具：反推需求文档与技术栈说明

> 文档用途：用于技术分享、项目复盘、后续需求对齐。  
> 生成时间：2026-05-07  
> 当前版本参考：V26.5.7.12

## 1. 项目定位

糖三角是一款面向抖音直播间的桌面采集与分析工具。

核心目标是：在用户已登录抖音的前提下，采集直播间内的评论、进场、互动、送礼等公开可见数据，并在桌面端进行实时展示、筛选、高亮、导出和重点用户追踪。

项目不是单纯的网页爬虫，而是一个 Electron 桌面应用，内部集成本地 Node 服务、浏览器自动化采集、SQLite 本地存储、React 前端展示和 Excel 导出能力。

## 2. 目标用户

- 直播运营人员：关注直播间互动质量、礼物数据、重点用户行为。
- 场控或数据观察人员：需要实时看评论、进场、互动、送礼信息。
- 私域运营人员：需要标记特别关注用户，并在评论或送礼时快速识别。
- 数据复盘人员：需要采集结束后导出 Excel 留存数据。

## 3. 核心使用场景

### 3.1 登录后采集直播间

用户输入抖音直播间 URL，先点击“登录抖音”，完成登录后点击“开始采集”。软件复用已登录浏览器环境进入直播间，开始采集数据。

关键要求：

- 必须支持登录态采集，因为未登录状态可能无法获取完整礼物区数据。
- 登录窗口可复用，避免重复启动 Chrome。
- 登录后即使前端状态刷新延迟，也不应阻止开始采集。
- 采集过程中需要尽量保持直播间页面活跃，避免页面暂停导致采集暂停。

### 3.2 实时观察直播数据

采集后，界面按模块展示：

- 用户进场
- 用户互动
- 直播间评论
- 用户送礼
- 神秘人列表
- 特别关注命中消息
- 版本日志
- 导出入口

关键要求：

- 评论区和送礼区需要实时刷新。
- 新消息应自动跟随到底部。
- 用户手动暂停跟随后，不强制滚动。
- 数据量大时不能明显卡顿。
- 评论和送礼内容换行后不能被遮挡。

### 3.3 神秘人识别与追踪

软件需要识别直播间中出现的“神秘人”相关用户，并汇总到神秘人列表。

当前规则包括：

- 昵称、用户 ID、主页链接、payload 字段中包含“神秘人”。
- 昵称、用户 ID、主页链接、payload 字段中包含“神秘王者”。
- 部分场景兼容昵称中包含 dou 的特殊身份用户。
- 普通用户在评论中 @神秘人 时，不应把普通用户误判为神秘人。

展示要求：

- 神秘人列表只展示神秘人相关用户，不展示所有用户。
- 最多展示 99 个神秘人用户。
- 最新活动靠前。
- 每个神秘人支持点击用户名打开主页。
- 每个神秘人提供“+”按钮，展开后显示该用户最近动态，例如评论内容、送礼信息、进场行为。

### 3.4 特别关注用户高亮

软件读取桌面 `highlight_users.txt` 文件，用于配置重点关注用户。

文件格式：

```txt
用户ID 备注
1215343001 重要客户
*dou* 关注dou相关用户
```

功能要求：

- 每行一条配置。
- 支持纯用户 ID。
- 支持用户 ID + 备注。
- 支持部分通配符规则。
- 只根据用户身份字段命中，不应误匹配 `douyin.com` 等公共链接内容。
- 命中后在评论区、送礼区等模块高亮。
- 特别关注弹窗只展示命中的消息，不展示完整关注用户列表。
- 备注用于辅助识别，但不应随意覆盖用户原始昵称。

### 3.5 噪音过滤

为减少无效信息干扰，需要屏蔽部分直播间页面元素误采集内容。

已覆盖场景：

- 连线倒计时，例如 `60、59、58`。
- 带秒数的倒计时，例如 `(27s)`。
- 主播账号发出的纯数字倒计时。
- 系统类、提示类、空白类、重复类消息。
- 同一条评论重复返回时需要前端去重。

### 3.6 数据导出

用户停止采集后，数据不应清空，并应支持导出 Excel。

要求：

- 停止采集后保留当前数据。
- 支持导出 Excel。
- 导出内容覆盖评论、进场、互动、送礼和统计信息。
- 采集结束后可自动保存到桌面或用户可访问位置。

### 3.7 桌面端体验

要求：

- Windows 桌面应用。
- 支持单文件版和安装包版打包。
- 安装包默认安装到 D 盘，减少 C 盘占用。
- 软件运行数据也尽量放到 D 盘，减少 C 盘压力。
- 窗口尺寸可记忆，下次打开复用上次尺寸。
- 顶部展示版本号和版本日志入口。
- 默认不展开版本日志。
- 支持多主题色。
- 避免过重动画、阴影、模糊效果影响性能。

## 4. 功能模块拆解

### 4.1 Electron 桌面壳

职责：

- 创建主窗口和子窗口。
- 启动内嵌本地服务。
- 加载 React 前端页面。
- 管理窗口尺寸、置顶状态、子窗口打开。
- 打包桌面应用。

相关文件：

- `apps/desktop/main.mjs`
- `apps/desktop/preload.cjs`
- `apps/desktop/package.json`
- `apps/desktop/scripts/*`

### 4.2 本地服务层

职责：

- 提供 REST API。
- 提供 SSE 事件流。
- 管理采集会话生命周期。
- 聚合统计数据。
- 读取特别关注文件。
- 导出 Excel。

相关文件：

- `apps/server/src/index.ts`
- `apps/server/src/capture-service.ts`
- `apps/server/src/event-bus.ts`
- `apps/server/src/exporter.ts`

### 4.3 浏览器采集层

职责：

- 使用 Playwright 启动 Chromium。
- 复用登录态浏览器 profile。
- 进入直播间页面。
- 从页面 DOM / React 数据 / 文本节点中提取直播事件。
- 去重、分类、过滤噪音。
- 保持页面活跃，降低暂停风险。

相关文件：

- `apps/server/src/collector.ts`
- `apps/server/src/playwright-runtime.ts`
- `apps/server/src/utils.ts`

### 4.4 数据存储层

职责：

- 使用 SQLite 存储会话和事件。
- 查询历史事件。
- 查询统计数据。
- 查询神秘人统计。

相关文件：

- `apps/server/src/db.ts`
- `storage/douyin-live-suite.db`

### 4.5 前端展示层

职责：

- 展示采集状态。
- 展示进场、互动、评论、送礼列表。
- 展示神秘人列表窗口。
- 展示特别关注命中弹窗。
- 管理主题、筛选、跟随、版本日志。
- 做前端去重、限流、虚拟化和渲染优化。

相关文件：

- `apps/web/src/App.tsx`
- `apps/web/src/api.ts`
- `apps/web/src/types.ts`
- `apps/web/src/styles.css`

## 5. 数据流说明

### 5.1 启动流程

```txt
用户打开 EXE
  -> Electron 启动
  -> Electron 查找可用端口
  -> 启动本地 Fastify 服务
  -> 加载 React 静态页面
  -> 前端请求 /api/sessions/active、/api/browser/state 等接口
  -> 主界面进入可操作状态
```

### 5.2 采集流程

```txt
用户输入直播间 URL
  -> 点击登录抖音
  -> Playwright 启动持久化 Chromium profile
  -> 用户完成登录
  -> 点击开始采集
  -> 后端校验或复用登录态
  -> 创建采集 session
  -> Collector 进入直播间页面
  -> 提取原始事件
  -> 分类为 comment / entry / interaction / gift / log
  -> 写入 SQLite
  -> 更新内存统计
  -> 通过 EventBus / SSE 推送到前端
  -> 前端批量更新列表 UI
```

### 5.3 神秘人数据流

```txt
采集到事件
  -> 判断事件身份字段是否命中神秘人规则
  -> 排除普通用户 @ 神秘人的误判场景
  -> 生成 identityKey
  -> 写入 activeUserMap
  -> 更新 entry/comment/gift 计数
  -> 保存最近活动 activities
  -> 前端神秘人窗口读取 stats.activeUsers
  -> 按 lastActiveAt 倒序展示最多 99 人
```

### 5.4 特别关注数据流

```txt
程序启动或刷新
  -> 读取桌面 highlight_users.txt
  -> 解析用户 ID、备注、通配符
  -> 前端编译匹配规则
  -> 评论/送礼/互动事件进入列表
  -> 根据用户身份字段匹配规则
  -> 命中后高亮该消息
  -> 特别关注弹窗只展示命中消息
```

## 8. 性能优化现状

已做优化：

- 前端列表限制最大保留条数。
- 评论区、礼物区做重复消息去重。
- SSE 推送和前端批量处理，减少频繁全量刷新。
- 降低 UI 刷新频率，避免每条消息都立即触发完整渲染。
- 特别关注和神秘人规则做缓存/编译思路。
- 减少 box-shadow、backdrop-filter、transform 等可能影响渲染性能的样式。
- 列表区域使用虚拟滚动思路降低 DOM 压力。
- 神秘人列表最多 99 人，避免弹窗长时间累积过多数据。

仍然存在的性能边界：

- Chromium 直播网页本身资源占用较高，不完全由本软件控制。
- 直播间消息极高频时，采集、过滤、存储、推送、渲染都会产生压力。
- SQLite 写入和前端渲染虽然已优化，但长时间运行仍需要控制数据保留策略。
- 单文件 EXE 启动会受解包、安全扫描、Chromium 运行时加载影响。

## 9. 主要技术难点

### 9.1 抖音页面结构不稳定

直播间页面 DOM、className、React 数据结构可能变化，采集逻辑需要兼容多种结构。

应对方式：

- 多源提取：DOM 文本、属性、React payload、结构化礼物数据。
- 多层过滤：噪音过滤、重复过滤、倒计时过滤。
- 弱依赖固定 className，更多依赖文本特征和数据字段。

### 9.2 登录态可靠性

未登录时礼物区可能不可见或不完整，登录态必须稳定复用。

应对方式：

- 使用 Playwright persistent context。
- 保存浏览器 profile。
- 开始采集时后端主动校验登录态。
- 前端不把登录状态刷新延迟作为唯一拦截条件。

### 9.3 高频消息下 UI 卡顿

大量消息会导致 DOM 节点增加、React diff 压力增大、滚动跟随不稳定。

应对方式：

- 限制列表长度。
- 批量更新。
- SSE 降低轮询压力。
- 虚拟列表。
- 减少复杂 CSS 效果。
- 自动跟随逻辑和手动滚动逻辑分离。

### 9.4 神秘人误判

普通用户 @ 神秘人时，不能把普通用户当作神秘人。

应对方式：

- 身份字段命中优先。
- 评论内容命中需要额外判断。
- @ 场景下，如果发送者身份字段不含神秘人关键词，则排除。

### 9.5 特别关注误命中

`*dou*` 可能误命中 `douyin.com`，导致所有消息高亮。

应对方式：

- 匹配范围限制在用户身份字段。
- 不对公共 URL 域名做无差别内容匹配。
- 备注展示和用户原始昵称展示分开处理。

## 13. 技术选型总结

当前技术栈适合这个项目，原因是：

- Electron 能提供桌面入口、窗口管理、本地文件、打包分发能力。
- Playwright 能复用真实登录态浏览器环境，满足登录后采集需求。
- Fastify 适合轻量本地 API 服务。
- SQLite 适合本地单机存储，不需要额外部署数据库。
- React 适合快速实现复杂交互界面。
- ExcelJS 满足运营人员常见导出诉求。

不建议短期完全替换技术栈。更现实的优化方向是：继续优化采集稳定性、前端渲染性能、长期运行内存释放、打包图标和安装体验。
