# 糖三角软件改动总清单

生成时间：2026-05-08

说明：软件内版本日志已删除 2026-05-06 / V26.5.6.x 记录；本文档用于集中查看历史功能、UI、性能、打包和技术栈相关改动。

## 1. 功能类改动

- 新增神秘人识别列表，支持从进场、评论、送礼等来源识别神秘人。
- 神秘人列表按最新互动倒序展示，最新活动靠前。
- 神秘人昵称支持点击打开用户主页。
- 神秘人本人评论、送礼时支持高亮展示。
- 评论区中用户 @ 神秘人时，不再把普通用户误判进神秘人列表。
- 修复神秘人进入直播间未进入神秘人列表的问题。
- 神秘人列表增加“神秘王者”和昵称/身份中包含 dou 的识别能力。
- 修复 douyin.com 域名中的 dou 导致所有用户误入神秘人列表的问题。
- 神秘人列表只展示真实神秘人相关数据，不再展示所有用户动态。
- 神秘人列表去除热门礼物模块，让窗口更聚焦。
- 神秘人窗口增加单例逻辑，重复点击只聚焦已有窗口，不重复创建多个窗口。
- 神秘人列表限制展示数量，避免长期运行列表无限增长。
- 新增特别关注模块，读取桌面 highlight_users.txt。
- 特别关注支持用户 ID + 备注格式。
- 特别关注纯 ID 单行也可正常识别。
- 特别关注命中评论时高亮展示。
- 特别关注扩展到送礼区高亮。
- 特别关注改为仅按用户 ID 命中，不再用用户名兜底误命中。
- 特别关注通配符规则经过修正，避免 *dou* 误命中 douyin.com 域名。
- 特别关注启动时只读取配置，不扫描历史命中记录，开始采集后展示实时命中。
- 特别关注命中后不改写原始昵称展示。
- 神秘人同时命中特别关注时，神秘人列表最终恢复优先显示原始神秘人名。
- 特别关注命中弹窗改为只展示命中消息，不展示关注用户列表本身。
- 特别关注命中消息支持倒序展示，最新命中在上方。
- 修复 highlight_users.txt 中文备注乱码问题。
- 修复特别关注 ID 在评论区显示但送礼区不显示的问题。
- 修复特别关注命中记录中包含送礼命中，但送礼区未高亮的问题。
- 修复停止采集后数据被清空的问题。
- 停止采集后保留当前采集数据。
- 停止采集后支持导出 Excel。
- 支持导出评论、进场、互动、送礼和统计数据。
- 修复评论区重复展示同一条评论的问题。
- 增强评论区重复评论过滤，减少旧评论反复出现。
- 过滤匿名用户/系统噪音导致的倒计时内容。
- 过滤直播连线倒计时，例如 60、59、58、(27s) 等。
- 针对主播本人发出的纯数字倒计时 0-180 增加屏蔽规则。
- 修复评论中出现“匿名用户：0 ：内容”和“0：内容”重复展示的问题。
- 修复登录状态误显示“关注”的问题。
- 登录状态无法可靠识别账号名时，避免展示错误账号名。
- 登录后开始采集复用当前登录窗口，减少额外窗口创建。
- 保持直播间页面活跃，避免网页播放器暂停后采集暂停。
- 支持输入框中 Ctrl+A 全选 URL。
- Electron 全局禁用误触 Ctrl+A，但 URL 输入区域保留 Ctrl+A。
- 支持窗口置顶。
- 支持记录主窗口尺寸和位置，下次打开恢复。
- 主窗口 45 分钟自动重启机制被改为不自动重启。

## 3. 性能和稳定性整改

- 将前端事件队列由逐条消费改为批量消费。
- 服务端 SSE 从逐条事件推送改为批量事件推送。
- 前端支持批量接收 SSE 事件。
- 前端按更低频率批量消费展示队列，减少 React 高频渲染。
- 采集高峰期减少 UI 更新次数。
- 特别关注规则预编译复用，减少每行重复匹配开销。
- 列表行关键词、神秘人、特别关注状态预计算，降低渲染期重复计算。
- 降低统计刷新频率，避免高频 stats 请求抢占资源。
- 窗口移动/缩放期间暂停前端消息队列 flush，优先保证窗口拖动流畅。
- 窗口移动/缩放期间延迟处理 SSE 消息，移动结束后统一补处理。
- 前端待展示队列增加硬上限，防止长时间运行内存持续增长。
- 用户主页解析缓存增加 LRU 上限。
- 采集端去重 Map、礼物组合 Map、页面去重缓存增加硬上限。
- 神秘人活跃列表限制返回数量，减少渲染和内存压力。
- 当前会话 stats 改为写入事件时维护内存统计快照，减少统计接口全表扫描。
- 页面内视频资源继续拦截/暂停/静音，降低直播页资源消耗。
- 保持图片存在，同时降低视频播放和解码压力。
- 启动和空闲状态不加载历史评论、进场、送礼列表，减少打开等待和旧数据回流。
- 启动阶段去掉 Loading 窗口，减少额外窗口创建。
- 恢复小体积单文件包，不再附带 Chromium 目录。
- 打包压缩改为 normal，优化单文件启动等待。
- 列表虚拟滚动曾引入并测试，用于降低 DOM 渲染压力。
- 因虚拟列表出现底部空白、滚动条闪烁、自动跟随不稳，当前已回退为稳定渲染当前保留窗口。
- 当前评论、进场、互动、送礼每类保持约 120 条前端展示，避免 1000 条展示导致卡顿回归。
- 列表刷新禁用 transition、animation、transform、box-shadow 等容易闪烁的重绘效果。
- 主列表自动跟随改为按真实 DOM scrollHeight 定位。
- 长时间采集后旧缓存会自动释放，降低卡顿和崩溃风险。

- 打包文件名增加版本号，区分同一天多次版本。

- 支持单文件版打包。
- 支持安装包打包。

- 安装包和 exe 图标改为糖三角 Logo，避免 Electron 默认图标。

- 打包过程加入 native rebuild 缓存，未变更时跳过重建。
- 使用 normal 压缩策略，降低单文件自解压等待。
- 清理影响打包的运行中服务。

## 5. 技术栈评估和取舍

- 当前主技术栈：Electron 桌面端。
- 当前前端技术栈：React + TypeScript + Vite。
- 当前后端技术栈：Node.js + Fastify。
- 当前采集技术栈：Playwright 控制 Chromium / 本机 Chrome / Edge。
- 当前数据存储：SQLite / better-sqlite3。
- 当前实时通信：SSE。
- 当前导出：ExcelJS。
- 当前打包：electron-builder。
- 评估过目录版和单文件版启动速度、体积和杀软扫描体验。
- 评估过安装包是否能提升启动速度，结论是安装包不一定明显提升主程序启动，主要改善安装和覆盖体验。
- 评估过 WebView2 / 轻量启动方向，但当前没有整体替换主技术栈。
- 评估过不用 SSE 的其他协议，例如轮询、WebSocket，但当前 SSE 更符合单向实时消息推送场景。
- 结论：暂不替换整体技术栈，继续围绕 Electron + React + Fastify + Playwright + SSE 优化。
- 前端展示层后续如果要支持 500-1000 条以上展示，应重新设计稳定虚拟列表或快照层。
- 采集端资源瓶颈主要来自抖音直播网页和 Chromium，不完全由本软件前端决定。

## 6. 已回退或调整方向

- 虚拟列表曾上线测试，但因底部空白、滚动闪烁、自动跟随不稳，已回退到稳定窗口渲染。
- 启动 Loading 曾上线，但因启动速度和 Logo 空白问题，后续去掉。
- 目录版曾用于测试启动速度，最终仍保留单文件小体积方向。
- 拖动条样式曾改为更明显胶囊式，验收后恢复上一版，仅修复黑粉 hover 主题色问题。
- 部分高级 UI 动效被移除，优先保证大数据量下的稳定性和流畅度。
